# 通知策略方案（应用内 + 订阅消息）

**背景**：协作邀请、建群结果、审核结果等依赖用户**回到小程序**才能看到。设置中可关闭「协作类」应用内通知展示（`setting_notify_match`），与「必达」存在张力。  
**产品结论（2026-05）**：订阅消息真接入**依赖资质与模板**，短期以**应用内通知 + 会话列表强化**为主；额度上可先放宽演示（见 `token-manager` 与运营策略）。

---

## 1. 渠道分层

| 层级 | 载体 | 适用内容 | 说明 |
|------|------|-----------|------|
| L1 必达（长期） | 微信**订阅消息** | 待同意的协作邀请、超时前提醒 | 需用户授权、模板与类目合规；开发接入排期单列 |
| L2 默认 | 应用内 **`notifications` + 通知 Tab** | 建群成功、邀请已发、系统公告 | 已实现；依赖用户偶尔打开通知页 |
| L3 工作台 | **`conversations` 会话列表** | 待处理邀请条、群预览、新消息提示 | 已实现：待处理邀请条、`lastMessage`、本地「新」圆点 |
| L4 上下文内 | **`chat` 内邀请条 / 弱提示** | 陌生人匹配、协作状态 | 与 A8b 等一致 |

## 2. 与设置项的关系

- **关闭「协作类提醒」**（若仅隐藏列表而不删云端数据）：须在设置文案中说明：**「仅隐藏通知页中的协作类展示，不保证通过微信推送提醒；重要邀请请到会话列表查看待处理条。」**  
- 若未来接入订阅消息：**关闭应用内展示 ≠ 取消订阅授权**，二者在文案上拆开写清。

## 3. 短期落地（不接订阅时）

1. 会话列表顶部 **待处理协作邀请** 条（已接 `listMyPendingStrangerMatchInvites`）。  
2. 邀请多条时：首条进 `chat` 聚焦，其余引导至通知 Tab（已实现 Toast）。  
3. 计划 **待审** 徽章在会话列表展示（`reviewPending`）。  
4. 文档与「关于」页写明风险，避免用户以为关通知等于拒收业务消息。

## 4. 接入订阅消息后（条件具备时）

1. 在**关键动作后**触发授权：如首次开启「陌生人协作池」、首次发协作邀请前。  
2. 模板类型与微信类目对齐（协作类/社交类需审核）。  
3. 失败回退：仍走 L2–L4，不阻塞主流程。
