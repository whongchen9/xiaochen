## 1. Executive Summary

### 1.1 一句话产品

**在微信里，帮用户把需求聊清楚、落成可协作的「计划书」，用会话与群聊推进；辅以 AI 整理与改写；在规则明确前提下可连接「计划与陌生人」的匹配撮合。**

### 1.2 三句话展开

- **为谁**：有小团队 / 邻里互助 / 轻量自组织协作需求的用户（发起人 + 参与者为主）。  
- **解决什么**：需求分散在私聊里难对齐、缺少「计划 + 场域」、启动协作成本高。  
- **凭什么**：微信闭环 + 云开发降低工程成本；AI 降低「写清楚」成本；**不做中心派单、不托管资金**，边界清晰。

### 1.3 本期（MVP）目标（建议 6～10 周，可评审调整）

| 编号 | 目标 | 说明 |
|------|------|------|
| G1 | 用户能完成「**创建计划 → 编辑计划书 → 在会话中看到协作入口**」闭环 | 含基础资料与登录 |
| G2 | 用户能在「**协作群**」内收发消息，发起人可处理**入群申请**（若本期包含该能力） | 与计划绑定关系见 §5 |
| G3 | 用户能在**聊天页**使用 **AI 对话**，并可将要点反映到**计划书正文**（能力边界见 §6） | 失败可重试、有明确提示 |
| G4 | 用户能收到并处理**系统通知**（至少一类：协作/匹配相关） | 与开关策略一致 |
| G5 | （可选）**陌生人匹配**主路径可跑通「开关 → 扫描/邀请 → 同意/拒绝 → 进群」 | 若本期不做，整段移出 MVP 并更新 §3 |

### 1.4 成功标准（可量化建议）

| 类型 | 指标 | 目标（示例，需业务拍板） |
|------|------|---------------------------|
| 业务 | MVP 发布后 30 日内，完成「建计划并发第一条群消息」的用户占比 | ≥ X%（待定） |
| 体验 | 云函数核心路径失败率（`login` / `getPlanBoard` / `sendRoomMessage`） | < Y%（待定） |
| 工程 | 单一主仓 + 单一云环境可复现部署 | 文档与实际上线一致 |

### 1.5 关键取舍（冻结前必须签字）

| 类型 | 内容 |
|------|------|
| **做（MVP 内）** | 登录与资料、计划书看板、会话列表、群聊消息、AI 对话（扣次策略见 §9）、通知列表、发现页（若保留为 MVP） |
| **不做** | 中心派单、资金托管、为线下履约担保、旧版「广场 / 发帖」等已下线能力 |
| **二期** | 深度运营工具、复杂推荐、完整数据看板、多环境灰度等 |
| **当前实现说明** | 产品界面**不挂载**「小陈助手」悬浮组件；若产品要求恢复，须单独立项并更新范围 |

## 2. 背景与问题陈述

### 2.1 用户痛点

- 需求停留在口头，难以形成可分享、可对齐的「计划」。  
- 多人协作散落在私聊，缺少与计划绑定的「场域」。  
- 从「想清楚」到「拉人一起做」启动成本高。

### 2.2 商业与平台约束

- 平台**不托管资金**、**不为线下履约担保**；价格与成交由用户自行约定。  
- 遵守微信小程序及云开发、内容安全、用户隐私相关要求。

## 3. 用户细分与场景优先级

### 3.1 用户角色

| 角色 | 描述 | MVP 是否覆盖 |
|------|------|----------------|
| R1 发起人 | 创建计划、编辑计划书、邀请/配置匹配 | 是 |
| R2 参与者 | 查看计划、进群、发消息、处理邀请（若匹配开启） | 是 |
| R3 浏览者 | 仅预览公开信息（若产品定义存在） | 待定 |
| R4 管理员 | 审核计划等特殊动作（若业务存在） | 待定 |

### 3.2 核心场景（Job Story）与优先级

| ID | 场景（When… I want… So that…） | 优先级 |
|----|-----------------------------------|--------|
| S1 | 当我有一个模糊想法时，我想把它整理成计划书，以便邀请他人对齐 | **Must** |
| S2 | 当计划需要多人推进时，我想有群聊与消息记录，以便协作不断档 | **Must** |
| S3 | 当我写不清楚时，我想用 AI 帮我补全或改写，以便更快定稿 | **Should** |
| S4 | 当我想扩大协作面时，我想按规则开启匹配并处理邀请 | **Could**（纳入 MVP 则升为 Must） |
| S5 | 当有事找我时，我想在通知里看到并处理 | **Should** |

## 5. 业务规则（状态、权限、对象关系）

### 5.1 核心对象关系（产品需确认）

- **计划（Plan）** 与 **群聊（Room）** 关系：**1:1** / **N:1** / 其他（必须写死一种 MVP 策略）。  
- **AI 会话（Session）** 与 **计划**：是否允许「先有 AI 对话再生成计划」；计划删除后对群的影响。

### 5.2 计划状态机（草案 — 需与研发对齐字段）

| 状态 | 含义 | 允许操作（发起人 / 参与者） |
|------|------|------------------------------|
| draft（可选） | 草稿 | 仅发起人编辑 |
| active | 进行中 | 编辑规则待定 |
| done / archived | 结束 / 归档 | 只读或有限编辑 |

### 5.3 权限矩阵（草案）

| 动作 | 发起人 | 参与者 | 非成员 |
|------|--------|--------|--------|
| 编辑计划书正文 | ✓ | ？ | ✗ |
| 开关匹配 | ✓ | ✗ | ✗ |
| 发送群消息 | ✓ | ✓（成员） | ✗ |
| 审批入群 | ？（群主/发起人） | ✗ | ✗ |

（「？」表示必须由产品拍板。）

### 5.4 陌生人匹配（若纳入 MVP）

- 准入：计划需满足哪些条件才可参与扫描（完整度、开关、偏好）。  
- 邀请：超时、重复邀请、拒绝后冷却（若有）。  
- 合规：风险提示文案、举报/拉黑（若有）与 MVP 边界。

## 7. 关键流程说明（文字版；泳道图占位）

1. **冷启动**：打开小程序 → 云初始化 → 静默登录 → 进入默认 Tab。  
2. **建计划**：计划书编辑 →（可选）AI 辅助 → 创建计划 → 会话或通知出现入口。  
3. **协作**：会话列表 → 进入群 → 收发消息。  
4. **AI**：聊天页 → 发送 → 云端 `chat` → 展示回复 / 合并计划书（若开启）。  
5. **匹配（可选）**：计划书打开匹配 → 扫描 → 邀请 → 通知 → 同意 → 建群。

## 8. 体验与文案要点

- **空状态**：会话为空、通知为空、计划无摘要时的引导文案需产品提供终稿。  
- **错误态**：云失败、未配置 LLM、权限不足等，需统一话术（避免仅「system error」）。  
- **合规**：陌生人、线下见面、资金与履约等，需在「用户须知」与关键节点重复提示（见 `USER_NOTICE` 方向）。

## 10. 非功能需求（NFR）

| 类别 | 要求 |

| 性能 | 首屏可接受时间、列表滚动帧率（定目标值） |

| 发布 | 云函数 `service` 上传流程、环境 ID 管理规范 |

## 11. 风险与假设（RAID 摘要）

| 风险 | 影响 | 缓解 |
|------|------|------|
| 匹配合规与骚扰 | 高 | 规则、频控、举报路径、文案 |
| 云环境 / 上传遗漏 | 高 | 检查清单、单一环境主键 |
| LLM 成本与稳定性 | 中 | 限流、失败不扣次、降级文案 |
| 范围蔓延 | 高 | 本文 §1.5 冻结 + 变更记录 |

**关键假设**：用户愿意先完成「计划最小信息」再拉人；AI 为辅助而非唯一真相来源。
